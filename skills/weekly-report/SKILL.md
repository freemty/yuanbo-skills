# Weekly Report

Read `references/report-rubric.md` for the reporting voice and evidence
obligations.

1. Establish the reporting period and audience.
2. Gather commits, changelog entries, experiment findings, tasks, and other
   primary project evidence.
3. Organize by decisions and outcomes, not repository activity.
4. Preserve experiment IDs, numbers, blockers, and next commitments.
5. Verify every claim against a source before delivery.

Do not infer progress from commit count alone or fabricate next-week plans.
Create diagrams only when they clarify a genuinely new architecture.
